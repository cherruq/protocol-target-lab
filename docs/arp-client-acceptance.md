# Active ARP acceptance scope

The implementation targets4 active modes and7 request scenarios,15 legal
combinations. The default software test path is two real virtual Ethernet ports
on an owned internal Docker bridge. Existing-host-interface mode is a separate
real-NIC path and must never pass using same-interface outgoing captures.

The final worker image completed29 unit regressions and all15 current-config
software bridge profiles with8 same-image checks each (120 checks). Actual
incoming Ethernet metadata and full request/response hashes joined source events;
negative MAPPING injected complete canonical Replies rather than merely waiting
for silence. Extra target-runtime boundaries proved unrelated private-IP ARP
requests/replies do not contaminate negative_silent; complete canonical negative
Replies do increase unexpected responses without mapping. A RARP profile with
assignedIP distinct from sourceIP and10 retries passed8 checks. Runtime10ms
interval/timeout continued past61 actual sends without a query quota exit.
These extra target cases used a predecessor whose server/wire/Python bytes are
identical to final, verified by actual image file SHA256; they are not relabelled
as new final-client tests.

A client scheduling P2 was discovered after ordinary predecessor matrices passed:
OBSERVE/TIMEOUT could associate a captured identical frame with an already expired
older query. Original failure evidence is retained. The fix establishes a fresh
case baseline, confirms a live pending attempt after actual capture, and anchors
all later source proof to that same query. Observer calls share one aggregate
case budget; no reset/epoch/request nonce was introduced. The same actual2s
scheduling-delay counterexample now selects the fresh attempt instead of the
expired one. Two public unit regressions cover old-timeout borrowing and a
captured attempt already resolved by another peer. The general protocol absence
of a wire transaction ID remains explicit.

On the final image, real slow-drip HTTP connections were closed by the1.15s
observation point despite intermediate bytes; a ninth connection was rejected
while8 slots held partial headers, then fresh status worked on the same boot.
Incoming control traffic evicted bounded cached events while the response stayed
below64KiB and active querying continued. SIGTERM exited0 in approximately0.35s.
The main-loop heartbeat and actual five-instruction kernel readback remained
observable. These are bounded functional checks, not throughput acceptance.

Independent validation used its own byte codec across15 profiles (173 grouped
assertions). An original Linux7.0.0-42 kernel with iproute2 6.1.0 answered four
ordinary-ARP profiles: whois/response-fuzz, normal/nonzeroTHA, two mappings each.
The capture contains8 actual60-byte requests and8 kernel42-byte replies; every
source mapping response hash matches an actual captured kernel reply. Kernel
neighbor state was STALE as observed. The native layer ran the byte-identical
target predecessor and is connected to final by direct server/wire/Python hashes;
it does not validate an obsolete client. A separate read-only PCAP review checked
these counts and hashes without claiming another native execution.

Installed manager/CLI/Web/offline recovery, same-source adoption and old workspace
preservation, plus physical host-interface/LAN layers remain separate delivery
checks. Their results must be recorded from the actual final package and source;
worker/native software evidence does not presume shared deployment or merge.

Required assertions include all request byte mutations, strict full response
roles, RARP assignedIP distinct from sourceIP, bad-response absolute-deadline
behavior, per-attempt retry IDs and continuous service lifetime. Complete normal
Reply injection into every negative request must yield actual received rejection
and unexpected count, no mapping, then timeout without negative_silent. Pure
silence plus actual unrelated control ARP must still produce negative_silent.
Do not prewarm caches, filter valid role replies or change host neighbor/sysctl
state to hide failures. Short37 submissions and actual driver padding need their
own wire lengths/hashes, not a claim of a physical short frame from send length.

Actual kernel SO_GET_FILTER readback must equal the published five-instruction
ARP/RARP EtherType filter and canonical hash. Manager source proof also requires
actual PID1 AF_PACKET inode/ifindex and observer TCP ownership, boot/runtime nonce,
config identity and main-loop freshness before and after tests. Network adoption
uses immutable owned internal network ID/labels and exact endpoint ownership;
foreign endpoints block cleanup. Test peers are disposable; no permanent fake
peer is allowed. Stops, manager crashes, changed drafts and conflicts must preserve
the correct source/applied state and all prior protocol workspaces.

Original kernel ARP can independently prove WHOIS/nonzero-THA exchange and real
neighbor learning in an owned namespace. It does not prove a Linux RARP or InARP
server: those need a separate independent raw/RFC oracle. Kernel/packet captures
and same-image tests are distinct layers, not counts to add indiscriminately.
WiFi or physical L2 filtering is an observed environment boundary only after
actual attempts; it is not inferred from an interface name or absent wired carrier.
