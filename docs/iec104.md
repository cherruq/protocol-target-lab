# IEC104 workspace

This workspace runs real c104 2.2.1 and its bundled native lib60870 stack, with
one documented project compatibility correction for incremental TCP header
reads. The server has three finite in-memory point roles and provides no
physical control, system clock adjustment, reset service, TLS, file transfer,
or arbitrary command execution. One protocol workspace controls one RTU.

```json
{
  "bind_ip":"0.0.0.0","port":2404,"max_connections":16,
  "points":{
    "single":{"ca":1,"ioa":1,"value":false},
    "measured":{"ca":1,"ioa":100,"value":12.5},
    "command":{"ca":2,"ioa":1}
  }
}
```

The host binding accepts unicast/wildcard IPv4 and port 1–65535. The container
listens on internal IPv4 TCP 2404; Docker bridge publishing maps the selected
host endpoint without opening another listener. `max_connections` is integer
1–64. CA is integer 1–65534 and IOA integer 1–16777215; the three CA/IOA pairs
must be distinct. The allowed station set is derived from the configured CAs.
Unknown keys, nulls, booleans in integer fields and duplicate addresses fail
validation before native startup.

Point roles and types are fixed:

| Role | Native type | Meaning |
|---|---|---|
| single | M_SP_NA_1 | Boolean monitoring point; configured value is its startup value. |
| measured | M_ME_NC_1 | Finite float32 monitoring value; no periodic spontaneous report. |
| command | C_SC_NA_1, DIRECT | Direct single command, mapped to the configured single point, including across CAs. |

Measured JSON numbers are normalized to binary32; NaN, infinity and values
outside that range are rejected. For example, 0.1 is compared to its actual
float32 representation. Command has no editable initial value. A valid command
updates the associated single point in memory before the native confirmation.
This is simulated behavior and does not indicate physical execution.

The saved/applied `single.value` remains a startup setting. Runtime state may
legitimately change through commands and returns to the applied startup value
when the service restarts. Read/GI/health must not permanently compare the live
single value to its startup value.

## Native protocol behavior

c104 performs APCI/ASDU decoding, sequence/window handling, timers and protocol
confirmations. The Python server supplies only the finite point model and
command callback. Startup checks native `is_running` before logging ready.
Raw native receive/send events use 128-byte previews, full length/hash and a
truncation flag. Command events record actual decoded CA/IOA/type/COT and the
associated previous/new simulated single value. The process runs non-root in
the foreground, has no duration/request-count expiry, and handles SIGTERM by
stopping the native server.

- CONNECT uses distinct native STARTDT, TESTFR and STOPDT ACT/CON exchanges.
- Station interrogation uses QOI20: native ACT_CON COT7, actual monitoring data
  COT20, then ACT_TERM COT10. A command-only station legitimately returns 7/10
  with no monitoring data. Command points are not counted as GI telemetry.
- READ returns actual monitoring data with COT5. c104 2.2.1 also natively emits
  a C_RD_NA_1 ACT_CON COT7; the independent client requires both the matching
  confirmation and monitoring value, allowing either scheduling order.
- Direct C_SC_NA_1 uses request COT6 and native positive ACT_CON COT7. This
  native path does not emit ACT_TERM10; the wrapper adds none. GI termination
  must not be confused with command confirmation.

Native default protocol timers include delayed acknowledgement and idle-link
checks. An independent S-frame acknowledgement may be delayed or piggybacked
in an I-frame N(R); absence of a separate immediate S frame is not a failure.
Normal client requests use a three-second socket timeout and acknowledge
received I frames promptly. Dedicated native timer/fault timing tests require
their own appropriate budget and are not silently replaced with artificial ACKs.

## Documented incremental framing correction

The original c104 2.2.1 wheel disconnects if TCP delivers start byte 0x68 before
its length byte: the native nonblocking length read treats temporary no-data
as an error. A whole TESTFR, a split after the length byte and coalesced frames
work; a legal split after the start byte fails. The old image 0.1.0 and original
wheel/source are retained for regression provenance and are not the release
runtime.

Image `protocol-target-lab/iec104:0.1.1` rebuilds c104 from the unchanged public
source archive with `cs104-incremental-length-read-v1`. When the length read
returns zero, the correction preserves receive position 1 and waits for the
next chunk; negative reads still disconnect. All other native protocol logic
is preserved. This is an original project correction, not an upstream
backport. See `third-party/iec104/patches/README.md`, the exact unified diff,
and original/patch/result SHA-256 assertions. No stream proxy or changed test
packet boundaries hide the defect.

Required image capability labels are `iec104-response-schema=1`,
`iec104-client-schema=1` and `iec104-stream-framing=incremental-v1`, each under
the `io.protocol-target-lab.` namespace. The image also records the patch ID.

## Build and offline materials

```sh
scripts/iec104-fetch-deps.sh  # online: fixed base, public packages, compiler cache
scripts/iec104-images.sh      # network-disabled native source build and runtime
scripts/iec104-assets.sh      # dist/iec104-assets image/source/license manifest
```

The fixed Python 3.12 bookworm base, official wheel/sdist URLs and hashes,
build-tool archives and project patch hash are recorded in
`images/iec104/dependencies.lock.json`. The original official wheel is a
regression input; runtime installs the patched source-rebuilt wheel using its
generated SHA-256 pip lock. `/usr/share/doc/protocol-target-lab-iec104/build/`
contains the actual rebuilt-wheel hash and install lock. The source rebuild
uses network-disabled pip, CMake, compiler and make; it does not claim to be
byte-identical to an upstream wheel.

The compiler image `protocol-target-lab/iec104-build:2.2.1` is prepared online
from the same base. Preparation records its image identity and Debian package
versions under dist/. The runtime needs no additional host Python installation,
compiler or package manager. To reproduce on a fresh offline build machine,
transfer the fixed base and prepared compiler image using docker save/load,
alongside this public source tree and its locked packages. Runtime assets are
an installation bundle, not a compiler-image cache export.

Complete original c104 source, bundled lib60870/mbedtls/pybind11 sources and
licenses, project patch/application recipe, original wheel, build-tool archives
and worker sources accompany the runtime/export. c104 and lib60870 retain GPL
terms, and other native components retain their original licenses. Root MIT
notices do not relicense the native library. See `third-party/iec104/README.md`.
GPL corresponding source/build information is public delivery material, not
private reference data hidden in .local.

## Read-only and simulated-command client

The same image contains `/opt/protocol-target-lab/client.py`; override the
server entrypoint for a one-shot run:

```sh
docker run --rm --network=host --entrypoint python3 protocol-target-lab/iec104:0.1.1 \
  -u /opt/protocol-target-lab/client.py --host 127.0.0.1 --port 2404 \
  --method ALL --path station \
  --config-json '{"bind_ip":"0.0.0.0","port":2404,"max_connections":16,"points":{"single":{"ca":1,"ioa":1,"value":false},"measured":{"ca":1,"ioa":100,"value":12.5},"command":{"ca":2,"ioa":1}}}'
```

Methods are CONNECT, GI, READ, COMMAND or ALL; each selected case runs twice.
`--path` is `station`. GI covers every configured CA, including a command-only
station. The client independently parses actual TCP framing and I/S/U frames,
N(S)/N(R), ASDU counts/SQ, type, COT, PN/TEST/OA, CA, IOA, quality and value.
It rejects malformed reserved bits/shapes and uses fragmented sends; it does
not share the native server's parser or invent a server acknowledgement.

COMMAND temporarily changes the simulated single point: read its actual
current value, issue the opposite direct command, verify native confirmation
and READ/GI state, then restore the prior actual value in finally and verify
it again. Recovery uses a fresh bounded connection even if the original
connection failed. Ten seconds of the absolute 30-second budget are reserved
before mutation; every restore socket operation remains inside that deadline.
Operation failure or restoration failure makes the whole check fail. The
client does not rewrite configuration or start a service.

stdout is one JSON result with passed/checks/summary/seconds; pass exits 0 and
failure exits 1. Checks include structured requests, monitoring snapshots,
command/restoration evidence and `response.trace` with bounded wire previews
and decoded receive frames. Original sizes/hashes are retained. The report is
capped at 512 KiB, each socket at three seconds, and the full run at 30 seconds.
Invalid input, malformed packets, wrong values, unreachable targets and failed
restoration all produce structured failures.

```sh
python3 -m unittest discover -s workers/iec104 -p 'test_*.py'
```
