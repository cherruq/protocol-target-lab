# IEC101 dual-channel software serial target

The fixed IEC101 workbench runs both channels simultaneously in one owned container. Each listener has an independent raw PTY and lib60870-C 2.4.1 native slave process per TCP session. The single profile uses link/COT/CA/IOA widths 1/1/1/1; the double profile uses 2/2/2/3. Both profiles are mandatory. Each admits one master connection and promptly closes a second connection without a fabricated protocol response.

The required configuration has `wire_profile: "iec101-unbalanced-dual"`, `bind_ip`, `serial`, `single`, and `double`. Serial is the fixed software termios request `{baud_rate:9600,data_bits:8,parity:"N",stop_bits:1}`. Each channel requires `port`, `link_address`, `originator_address`, `common_address`, `single_char_ack`, and `point:{ioa,value}`. The two host TCP ports must differ. Single link/common addresses are 1–254, IOA 1–255 and OA exactly 0; OA is absent from one-byte COT and reports as null. Double link/common addresses are 1–65534, IOA 1–16777215 and OA 0–255. Point values and single-character-ACK switches are booleans. Null, unknown keys, duplicate keys and integer booleans are rejected.

Only host-configured TCP ports publish to container 24741 and 24742. There is no physical serial mount or privileged access. Normal disconnect reclaims only its own child/PTY. Unexpected native child, critical pump/listener/logger failure exits the entire group after reaping resources, allowing the manager to recover the full applied configuration. Stopping the manager alone preserves the owned container; adopting it checks both mappings and the complete configuration identity.

The native slave handles Reset, Status, confirmed user data and class1/class2 polls, including shared FCB duplicate detection. A new session has one configured M_SP_NA_1 spontaneous COT3 sample. Station GI QOI20 uses native class1 ACT_CON7, official lazy class2 M_SP COT20, then class1 ACT_TERM10. The client polls for all three application results; a link ACK alone never establishes GI success. E5 is a legal ACK/empty response when configured; actual ACD/DFC flags are interpreted, not replaced with constants. There is no command, hardware output, secure authentication or balanced-link claim.

Run the same-image independent Python master with:

```sh
python3 /opt/protocol-target-lab/client.py --host 127.0.0.1 \
  --port 24741 --secondary-port 24742 --method ALL --path dual \
  --config-json "$APPLIED_CONFIG_JSON"
```

Methods are `RESET_STATUS`, `CLASS2`, `GI`, `STREAM`, `ALL`; paths are `dual`, `single`, `double`. Each case runs two rounds per selected channel, with simultaneous dual-channel sessions for `dual`. ALL/dual gives 16 checks, including duplicate-FCB cached replay and real fragmented/coalesced bytes. Reports contain bounded request/response frame traces, native link flags, ASDU addresses and point/GI results. Exit0 means every check passed; errors produce JSON and exit1. A check has an absolute 3-second budget, the full run 30 seconds and the report at most 512KiB. Final half-close waits for native/PTY cleanup and EOF before reusing a slot.

The PTY/TCP bridge forwards bytes transparently and does not repair malformed FT1.2 or produce ACKs. Its per-direction queue is at most64KiB, drain deadline3s, log queue256, raw preview128bytes and native log line4096bytes. The upstream serial reader has a finite character-read budget of approximately300ms. Fragmentation inside that budget is tested separately from slower partial frames; no unlimited TCP reassembly is claimed. Native marker tolerance and timing limitations are recorded by actual tests rather than hidden by bridge filtering.

For a test program that opens a serial device, use the separately installed `plabctl serial` helper on that test host. It provides two root-owned stable paths `/run/protocol-target-lab/serial/iec101-a` and `iec101-b` through its own PTY/TCP connections. Both must be visible in the consuming process's devpts namespace and permitted by its device/group policy. The server container's private PTY path is not a host device. Do not substitute user-owned `/tmp` symlinks or change global protected-symlink settings. Direct wire tests do not require this helper.

Prepare sources/compiler online with `scripts/iec101-fetch-deps.sh`, build offline with `scripts/iec101-images.sh`, and export with `scripts/iec101-assets.sh`. The pinned original GPL source archive, project native wrapper, full COPYING, lock, build recipes and Python sources accompany the runtime and assets. Runtime image `protocol-target-lab/iec101:0.1.0` uses a digest-locked Python3.12 base. Offline rebuilding requires the prepared build image and locked base; this is not a distribution of complete Debian/CPython compiler sources. Native wrapper/library are GPL-3.0-or-later, autonomous Python is MIT, and base software keeps its own terms.

This is real IEC101 FT1.2/ASDU software interaction through PTY/TCP, distinct from IEC104. It does not establish RS232/RS485 electrical behavior, physical parity/line rate, half-duplex direction control, bus arbitration, interference tolerance, field device operation or physical relay measurements.

The fixed upstream parser accepts some malformed marker bytes when the remaining length/address/checksum are consistent: real tests observed an ACK for a variable frame with a changed final 0x16 or inner 0x68. The bridge preserves this native tolerance and the raw evidence; this target does not claim strict rejection of every malformed FT1.2 input. A 120ms fragmented request was accepted; a 400ms gap expired in the upstream serial reader. These are software stack boundaries, not electrical timing measurements.
