# PROFINET laboratory workspace

One owned container runs three concurrent identities: a newly compiled p-net 0.2.0 DCP native process, and independent software PTCP nodes with and without FollowUp. Their actual data MAC addresses are distinct. The managed source uses a read-only root filesystem and a private2MiB `/run/protocol-target-lab` tmpfs; only the native store volume is persistently writable. The management interface and unpublished read-only observer are separate from the new data interface and two private macvlan children. The source needs `NET_RAW` and `NET_ADMIN` inside its private network namespace; one-shot peers need only `NET_RAW`. No host interface, route, clock or existing protocol service is configured by the worker.

This is a finite software laboratory profile. It does not provide cyclic PLC I/O, IRT, a hardware clock, physical LED/GPIO, media transport or PI certification. Upstream p-net PTCP is a stub; PTCP behavior here is explicitly software. Native p-net may also open its internal UDP34964 and LLDP facilities; their complete functionality is outside this profile.

The six required configuration fields are `wire_profile`, `link`, `test_peer_mac`, `dcp`, `ptcp_n`, and `ptcp_f`. See the public configuration schema and [runtime-contract.json](../workers/profinet/runtime-contract.json). All four configured MACs are nonzero unicast, canonicalized to lowercase, and distinct. The data network accepts external tool endpoints and arbitrary valid requestors; the disposable test-peer MAC is not access control. A live external endpoint prevents empty-network removal and is never detached or killed automatically.

`dcp.initial_station_name` and `initial_ip_suite` initialize a **new** native store. Existing native values survive source replacement, manager restart, package upgrade and reinstallation. Editing an initializer does not overwrite current or permanent settings. Package remove/purge retains the native volume, trusted ownership/recovery receipt and deployment UUID. After purging configuration, restore the original configuration explicitly; the manager does not automatically import an arbitrary orphan store. Callers using a custom data directory are responsible for preserving it and invoking stop-all with that directory; package cleanup does not scan arbitrary external paths. Runtime current values, native nonvolatile-memory values, operating-system addresses/routes, and observed native file saving are separate views. An empty or unusual native runtime name remains visible even if the initializer form would reject it.

Station initializers use lowercase DNS-style labels, total1..240 ASCII bytes, no trailing dot or empty labels, and reject the reserved first-label `port-NNN`/`port-NNN-NNNNN` and four numeric labels. An unconfigured IP suite is exactly all zero. Otherwise native-valid host addressing is required: contiguous mask, nonzero nonloopback unicast host, no subnet/broadcast host; `/31` and `/32` have no valid native host under this fixed native version. Gateway zero is allowed, otherwise a same-subnet valid host. New data addressing must not overlap the actual management network or another connected interface.

N supports `good`, `wrong-seq`, `bad-tlv`, `wrong-port`, and `old-seq-first`. F additionally supports `missing-follow-up`, `truncated-follow-up`, `follow-up-reserved`, `follow-up-padding`, `follow-up-duplicate-port`, and `follow-up-bad-end`. F's required `truncated_follow_up_size`16..45 persists while inactive. Applying one node's fault does not disable or replace the other node.

Native DCP responds to Identify/Get/Set. `ALL` performs seven reads twice, two N Delay, two F Delay, and two each Sync, Sync+FollowUp and Announce, observing **both** PTCP processors for the latter three. This produces24 checks and26 transmitted request frames. Good configuration yields26 actual incoming response frames:20 selected matches and6 legitimate responses from the other Delay node. Current fault configuration changes those response counts. Each N Delay request emits1 frame, or2 for `old-seq-first`; F emits1 for `missing-follow-up`,4 for `old-seq-first`, otherwise2. Malformed/truncated applied outputs are checked as actual opaque bytes, not silently discarded by a normal decoder. Sync/Announce have no wire ACK: fresh request hashes and actual accepted processing events provide that observation.

Optional `DCP_WRITE_STATION_TEMP` and `DCP_WRITE_IP_TEMP` are one transaction each. They require a stable, AR-free, OS-consistent baseline and complete native save observation. A temporary Set clears the corresponding nonvolatile native field. The client therefore restores with qualifier1 only when the old target field was permanent/current-equal, and qualifier0 when the old target nonvolatile field was empty/zero. A mixed, unrestorable target baseline is unavailable before writing. Other semantic fields must remain unchanged. Detected foreign mutation prevents restoration rather than overwriting it; DCP has no compare-and-set, so a check-to-Set race cannot be eliminated. `restoration_complete` is distinct from disposable-client cleanup. The overall90-second client deadline includes a reserved30-second restoration budget. Neither failure nor cleanup deletes the native store.

`DCP_SIGNAL` validates native ACK and the native C software callback's three1Hz flashes (six transitions), twice. It does not claim a physical LED. Preexisting or concurrent signal activity can make the check unavailable/ambiguous.

Source invocation is `python3 -u /opt/protocol-target-lab/server.py --config-json FULL_JSON`. It requires the four manager-controlled environment fields `PLAB_RUNTIME_ID`, `PLAB_DEPLOYMENT_ID`, `PLAB_INSTANCE_ID`, and `PLAB_STORE_NONCE`. A named, owner-labelled native volume is mounted at `/var/lib/protocol-target-lab/profinet-native`; the source holds an exclusive writer flock. The same newly compiled C application exports exact file ABI sizes and validates known filenames, ownership, regular-file type, magic/version and semantic IP/name state before native initialization. Unknown, truncated, corrupt or unmarked existing files are preserved and refused. Native nonvolatile memory is not treated as proof of filesystem fsync.

Callbacks reside beside the native ELF in an immutable image directory. This native version searches `/bin:/usr/bin:<ELF directory>` and executes with an empty environment. The typed callback uses an absolute interpreter and a private root-only context, checks the actual native parent PID/start ticks/ELF hash and data/management identities, applies only the new data interface and explicit data default route, and records intent/readback/error independently of native ACK. A native successful Set can coexist with an OS-apply failure; the parent compares actual data addresses/default route with sampled native current values, including native states where no callback is invoked; the observer exposes that divergence rather than rewriting ACK or resetting storage. Overall readiness denotes the three bound/live processors; `network_apply.confirmed=false` remains an independent OS-apply diagnostic. Optional write tests require confirmed OS state.

The built-in disposable peer joins both exact networks with manager-validated test ownership labels. Arbitrary external tools may join only the data network; the management network remains restricted to the source and exactly owned test peers. An external same-image client uses the generated host-veth template with `--network host`, only `NET_RAW`, the actual host-side data-veth MAC, and the source actual management IPv4 for the private observer. Alternatively an administrator can arrange an explicit read-only observer path without joining an arbitrary endpoint to the management network. Ethernet traffic still traverses the actual data link; observer forwarding does not proxy protocol frames. Run the image with `--entrypoint python3`, then `/opt/protocol-target-lab/client.py --config-json FULL_JSON --interface auto --observer-host MANAGEMENT_IPV4 --observer-port 18092 --expected-boot-id BOOT_UUID --expected-runtime-id RUNTIME_HEX --method ALL --path suite`. `auto` resolves the uniquely matching configured test-peer MAC. An external endpoint may specify `--peer-mac ACTUAL_MAC`; it must match its actual data NIC. The peer uses `ETH_P_ALL` plus a narrow8892 kernel filter and explicit receive check, so a host-side bridge veth is observed before bridge protocol redirection. Interface names are discovered from actual MACs; management/data may be assigned different `ethN` names in different containers. No Docker socket is mounted into a peer. This fixed native version retains its upstream three-second SAM single-requestor-MAC window for Get/Set. The client waits at most3.5seconds for an observed different actor to become idle within its existing90-second budget; ongoing external traffic can still make the test unavailable. Tools using different MACs should be staggered. The native library is not patched to bypass SAM.

The private observer binds only the actual management IPv4 at18092. It supports read-only `GET /v1/status` and `GET /v1/events?after=CURSOR&limit=1..16`, with optional node/query-hash filters. Requests have an absolute1-second deadline,8 concurrent slots,8KiB header limit,64KiB response limit, and a256-event ring. Full frame hashes and bounded128-byte previews distinguish source TX submission from actual peer reception. Native tap records do not attribute a packet to a PID; immutable code and independently inspected native process/socket ownership qualify the origin claim.

Prepare fixed inputs explicitly with `scripts/profinet-fetch-deps.sh`; `scripts/profinet-images.sh` builds with networking disabled. `scripts/profinet-assets.sh` exports the runtime plus complete native archives, thin app, recipes, licenses, wrappers and prepared compiler input. Runtime import loads only the protocol runtime. Compiler input is loaded explicitly only for source rebuilding. The optional public compiler preparation recipe is `images/profinet/build.Dockerfile`; refreshing a compiler input requires an explicit lock-profile update and is not claimed bit-identical to the released input. The public base's Python/OS notices remain present; this does not claim a complete rebuild of the base operating system or bit-identical output across arbitrary toolchains.

Current worker evidence is recorded privately by actual image identity. Early fixture/setup failures and subsequent corrections are retained separately. Public end-to-end release acceptance is reported by the phase acceptance document after independent review and deployment, rather than inferred from source availability.
